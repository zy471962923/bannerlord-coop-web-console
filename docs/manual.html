01项目简介

Bannerlord Coop 是一个让《骑马与砍杀 2：霸主》支持多人联机的模组，它自带一个专用服务器 （Dedicated Server）。这个服务器跑起来就是一个全屏终端界面：所有操作靠敲命令， 所有信息靠滚屏。开服、停服、存档、踢人、看谁在线，全在下图这样的窗口里完成。

痛点

  • 看不见——服务端只有 ASCII 终端，1000 多行日志滚过去就找不到了，也没有搜索。
  • 管不了——想备份存档得先敲 save，再手动去 Documents 里找文件夹打包。
  • 查不到——谁在线、谁等级多少、装备了什么、人在卡拉迪亚哪个角落，终端里都没有。
  • 离不开——专用服必须一直开着，人一走开就不知道刚才发生了什么。
  • 看不懂——服务端只输出英文，中文玩家看着吃力。

这个工具做了什么

它是一个独立运行的本地小网站（Node.js，零前端框架），把这些事包了一层：

  • 用真实伪终端（ConPTY）跑服务端，所以服务端以为自己在跟人交互，TUI 完整可用； 同时把终端字节流解析成状态、日志、玩家列表。
  • 把服务端的英文日志和官方中文包对照，城镇、城堡、装备、技能、perk 全部显示中文。
  • 从存档和模块导出文件里读出每个玩家的等级、装备、部队、技能、位置， 并画在一张可缩放拖动的卡拉迪亚地图上。
  • 一键存档 + 打包备份 + 一键恢复，带备注。
  • 全部路径、端口都可以配置，不写死盘符，整个目录拷给别人就能用。
它不改游戏。没有 DLL 注入，没有改服务端二进制，只是启动它、读它的输出、按它的规则发命令。 所以服务端升级后大概率还能用；真有格式变化，改的是控制台的解析层。

适合谁

自己开联机服、拉朋友一起玩的人。不需要懂 Linux、不需要公网服务器， 一台常开的 Windows 电脑 + ZeroTier / 内网就能跑起来。

状态栏（一直可见）

顶部常驻五颗信息胶囊：运行状态（未运行／启动中／运行中／停止中）、阶段 （boot／loading／serving）、在线人数、运行时长、版本号； 右侧是启动服务器／停止／强制结束三个按钮。

阶段（phase）比状态更重要。"运行中"只代表进程还活着，只有 serving 才代表世界已经载入完、玩家能连进来。从点"启动"到 serving 通常需要 55～60 秒。

网络与端口

端口协议用途默认
控制台TCP浏览器访问的网页端口7788
游戏UDP玩家连服务器用的端口，必须放行4200

控制台默认监听 0.0.0.0（所有网卡），所以同机器用 http://127.0.0.1:7788，同局域网／ZeroTier 用 http://本机IP:7788。启动窗口会把所有可用地址直接打印出来，复制即可。

关于 0.0.0.0。它包含公网网卡。如果你的机器直接暴露在公网、又没有设访问口令， 任何人打开这个地址都能启停你的服务器、恢复你的存档。请务必读第 09 节。 只想局域网用，把监听地址改成 auto（只放私有网段）；只给自己用，改成 127.0.0.1。

目录约定

下面三种目录是三个不同的地方，初次使用最容易搞混：

# 1. 服务端（游戏安装目录下）
D:\SteamLibrary\steamapps\common\Mount & Blade II Bannerlord\
  └─ DedicatedServer\BannerlordCoopServer.exe

# 2. 控制台（本压缩包，随便放哪）
D:\CoopConsole\
  ├─ server.js  start-console.bat  config.json
  └─ ……

# 3. 存档与配置（固定跟着 Windows「文档」走）
C:\Users\你的用户名\Documents\Mount and Blade II Bannerlord\CoopData\
  ├─ DedicatedServer\Game Saves\        # 存档
  ├─ DedicatedServer\logs\              # 服务端日志
  └─ mod-config.json                    # 玩法配置

控制台会自动探测这三个位置：从自己所在目录往上找 5 层，看哪层有 DedicatedServer\BannerlordCoopServer.exe；存档目录按当前 Windows 用户名推算。 所以把控制台放进游戏根目录下通常什么都不用配。

04安装与首次启动

第 1 步：解压

把压缩包解压到不含中文、不含空格的路径，例如 D:\CoopConsole。 路径带中文有时会让 Node 的某些原生模块找不到文件，虽然多数情况没事，但没必要冒险。

第 2 步：自检路径（推荐）

在该目录按 Shift + 右键 →「在此处打开 PowerShell 窗口」，或者直接双击同目录的 check-config.bat（若包内提供了），执行：

node lib\config.js

它会逐项打印并标注 ✓ 存在 / ✗ 不存在，以及该怎么改：

  ✓ 配置文件  D:\CoopConsole\config.json
  ✓ 服务端目录 D:\SteamLibrary\…\DedicatedServer
  ✗ 存档目录  C:\Users\某某\Documents\…\CoopData
       → 先启动过一次服务端，或在 config.json 里写 "coopData"

第 3 步：启动控制台

双击 start-console.bat。窗口里会出现一个地址列表：

  Bannerlord Coop 服务器控制台
  监听      : 0.0.0.0:7788（对外）
  监听来源  : 地址 = 内置默认值，端口 = 内置默认值（改 config.json 后重启生效）
  本机打开  : http://127.0.0.1:7788/
  局域网    : http://<本机IP>:7788/          [WLAN]
  ZeroTier : http://<本机IP>:7788/          [ZeroTier One]

0.0.0.0 是监听地址，不是给你在浏览器里敲的。浏览器要敲具体那张网卡的 IP， 上面几行已经替你列好了。默认全网卡监听，不按来源 IP 过滤 —— 谁能连上这台机器的 7788 端口，谁就能打开面板。要缩窄范围请看第 09 节的 host 说明。

不要关这个黑窗口。服务端跑在它的伪终端里，窗口关掉 = 服务器一起停。 想长期挂机见第 08 节。

第 4 步：打开控制台并启动服务器

  1. 浏览器打开 http://127.0.0.1:7788；
  2. 点右上角「启动服务器」；
  3. 状态栏从「启动中 / boot」变成「启动中 / loading」，约 55～60 秒后变成 「运行中 / serving」，此时玩家才能连进来。

第 5 步：放行防火墙

要让别人连进来，游戏端口（默认 UDP 4200）必须放行。以管理员身份运行 open-firewall.bat， 它一次放行控制台 TCP 端口与游戏 UDP 端口：

open-firewall.bat            :: 默认 7788 / 4200
open-firewall.bat 7788 4200  :: 自定义端口时显式指定
部分机器上 Windows 防火墙的三个配置文件都已关闭，此时不需要放行也能连。 但换机、换网络、或者开了第三方安全软件时，这一步省不了。

05界面总览

整个界面只有一页，八个标签，靠顶部导航切换。地址栏会记住你当前在哪个标签 （例如 http://127.0.0.1:7788/#map），可以直接收藏某一页。

几处一眼要认出来的地方

位置含义
左上「BC」标产品标识，没有功能。
中间五颗胶囊状态／阶段／在线人数／运行时长／版本。点不动，纯展示。
右上三个按钮启动服务器（未运行时可用）、停止（优雅停止，会先发 stop 等它自己退，最多等 45 秒）、强制结束（前两步无效时才用，直接杀进程树）。
标签上的小数字玩家档案上的数字是在线人数，存档备份上的是备份份数。
工具栏最右的灰字当前日志文件名、最后更新时间这类上下文信息。
刷新页面不会让服务器重启。控制台和浏览器是分开的两个进程， 关掉浏览器、换台电脑打开同一个地址，看到的都是同一个服务器状态。

06各标签详解

6.1　实时日志

服务端每一行输出都会进来。默认勾选「隐藏堆栈噪音」，把 .NET 异常堆栈和载入期刷屏折叠掉。

  • 过滤框：输入关键字即时过滤；写 -词 表示排除（例：player -telemetry）。
  • 等级下拉：全部／只看重要（警告、错误、SERVING 这类关键行）／警告及以上／只看错误。
  • 自动滚动：取消勾选后日志不再往下跑，方便往上翻着看。
  • 下载日志文件：把整份日志文件拉下来，排查问题时给别人看很方便。

6.2　TUI 镜像

把服务端的全屏终端按字符网格还原：状态栏、日志区、玩家列表、底部命令行，位置和颜色都对齐。 服务端刷新时这里跟着刷新。

图里那段红色堆栈不是故障。服务端每 60 秒会尝试上传一次遥测数据， 它的上报域名在部分地区连不通，于是每次都失败并打印一大块 SSL 异常。功能上没有任何影响， 在「实时日志」里勾着「隐藏堆栈噪音」就看不见它。

6.3　玩家档案

每个玩家一张卡片。数据来自两个地方：存档里的配对文件（锻造、交易、社交、行囊） 和游戏内模块每 15 秒导出一次的玩家详情（等级、家族、装备、部队、技能）。后者没部署时， 卡片仍然能显示，只是装备和技能是空的。

  • 卡片头部：头像块（姓名首字）、名字、等级、家族/势力、SteamID64、在线或离线标记。
  • 锻造总熟练：把各武器专精加总，一眼看出谁在打铁。
  • 专精条：投掷／弓／长杆／弩／双手／单手等，按熟练度排序取前几项。
  • 当前位置：世界坐标 + 最近的地标名（例如「附近 弗林托格堡」）。
  • 行囊：按价值取前几件，含数量。
  • 往来与家族：村庄、商队、工坊、竞技场大师、是否开放竞技大会。
  • 查看详情 →：展开装备槽、坐骑、部队编成、技能与属性点。
「附近地标」是把玩家坐标和地图上 120 个聚落做距离比较得出的，不是游戏原生数据。 所以它给的是最近的那个城镇或城堡，不一定是玩家正站在里面。

6.4　地图

一张完整的卡拉迪亚地图，底图是社区制作的高清版本（见第 12 节致谢）， 上面叠了 120 个聚落的中文标注和所有玩家的实时位置。

操作效果
滚轮以鼠标位置为中心缩放。缩到较远时城堡名自动隐藏，避免糊成一团。
按住拖动平移视野（内容跟手）。
鼠标悬停聚落/玩家显示中文名（附带英文原名）。
复位视野回到能看全整张地图的默认视角。
刷新位置立刻重新拉一次玩家坐标，不用等自动刷新。
地图默认视角按你浏览器的窗口比例算，所以宽屏上两侧会多一点海面，这是故意的—— 如果强行铺满，上下会被裁掉 40%，反而看不到北方的雪原和南方的沙漠。

6.5　命令台

把常用操作做成按钮，剩下 136 条游戏命令做成可搜索的标签墙，点一下填进输入框，再回车发送。

分组内容
服务器状态status 打印端口与存档名、players 列出在线玩家、help 帮助
公告 / 推送say 文字 向全服发一条消息；预置了几条常用公告，点一下直接发
存档 / 保存save 立即存档、status 查看当前存档名
踢人选择在线玩家后点 kick；没人在线时显示「暂无在线玩家」
关服stop 优雅关服，会先存档再退出
命令全集搜索框 + 全部游戏命令，点一下填入
命令台是"直接对服务端敲命令"。像 campaign.add_gold_to_hero 这类作弊命令，服务端若禁用了作弊模式会直接拒绝执行，控制台会把报错原样显示出来，不会静默失败。

6.6　存档备份

  • 立即备份：勾选「先让服务器 save 再打包」时，会先发一条 save， 等存档真正落盘后再把整个 Game Saves 目录打包，避免打出正在写的半份存档。
  • 备注：写「打完第一场大战」这类话，以后翻备份能一眼认出来。
  • 恢复：把备份解回存档目录。服务器运行中会拒绝恢复（返回 409），必须先停服。
  • 删除：备份不会自动清理，页面显示总占用，自己按需删。

6.7　更新日志

直接从 GitHub Releases 抓取并排版，标注你当前跑的版本，顺便告诉你有没有新的。

6.8　配置

最上面一张卡片可以直接改路径和端口，八项一人一行，改完点「校验并保存」。 下面三张是只读的：游戏侧的 server-config.json、玩法设置 mod-config.json、以及当前解析出的所有路径。

三个按钮：

  • 校验并保存：先校验，通过才写入，校验不过一个字都不写。
  • 只校验：只看结果，不落盘。
  • 还原当前值：把输入框恢复成磁盘上正在生效的值。
存完必须重启控制台才生效。因为配置是控制台启动那一刻读进内存的常量。 重启会连带停掉服务端，起来后记得再点一次「启动服务器」。

07配置项

配置只有一个文件：控制台目录下的 config.json。它可以不存在—— 不存在时全部走自动探测。要生成一份带注释的模板： 

node lib\config.js --init

字段

字段说明默认
root服务端安装目录（含 DedicatedServer 子目录的那层）从控制台目录往上找 5 层
serverDir服务端目录本身；给了就不用 rootroot\DedicatedServer
coopData存档与配置根目录文档\Mount and Blade II Bannerlord\CoopData
savesDir单独指定存档目录coopData\DedicatedServer\Game Saves
backupDir备份存放位置控制台目录下 backups
port控制台网页端口7788
host控制台监听地址0.0.0.0
gamePort游戏端口（防火墙要放行 UDP）4200

允许 // 注释和尾逗号，所以手改不容易出错：

{
  // 服务端装在哪
  "root": "D:\\SteamLibrary\\steamapps\\common\\Mount & Blade II Bannerlord",
  // 默认全网卡；只想给局域网就改成 auto，只给自己用就改成 127.0.0.1
  "host": "0.0.0.0",
  "port": 7788,
}

host 的三种写法

写法含义
0.0.0.0默认。所有网卡，含公网网卡。局域网、ZeroTier、本机都能访问。
auto回环 + 所有私有网段（10.x / 172.16–31.x / 192.168.x / 100.64–127.x）， 公网 IP 不自动放。最稳妥的对外方式。
127.0.0.1只有本机能访问，别人打不开。
127.0.0.1,192.168.1.10逗号分隔，精确指定只听哪几个地址。

优先级（重要）

同一个配置项有多个来源时，按下面的顺序取第一个有值的：

端口    : 环境变量 COOP_CONSOLE_PORT > --port > config.json > 默认 7788
监听地址: 环境变量 COOP_CONSOLE_HOST > --host > config.json > 默认 0.0.0.0
其它路径: 环境变量 > config.json > 自动探测

页面上每栏下方那行灰字会直接告诉你「当前值来自 …」， 启动窗口也有一行「监听来源」，所以不用猜。

命令行参数

参数作用优先级
--local只监听 127.0.0.1（兜底默认值）低于 config.json
--host 192.168.1.10这一次就监听指定地址高于 config.json
--port 7790使用指定端口高于 config.json
start-console.bat              :: 0.0.0.0:7788（默认，全网卡）
start-console.bat 7790         :: 换端口（用于开第二个只读面板）
node server.js --local         :: 只本机
以前还有一个 lan 模式和配套的 start-console-lan.bat，已经删除。 默认监听地址改成 0.0.0.0 之后，全网卡本来就已经听得见，不需要再开第二个开关； 想缩窄监听范围请改 config.json 的 host（填 auto 即回环 + 私有网段）。
开第二个面板：主控制台正在跑服务器、不想动它，可以另起一个实例用不同端口 指向同一份日志。--port 之所以优先级高于配置文件，就是为了这个场景。 但注意第二个实例不要点"启动/停止"，它不拥有那个服务端进程。

08日常运维套路

开服

  1. 双击 start-console.bat，窗口留着别关；
  2. 浏览器打开控制台，点启动服务器；
  3. 等状态栏变成运行中 / serving（约 60 秒），把地址发给朋友。

关服

按顺序试：停止（优雅，会先存档）→ 还不停就 强制结束 → 最后才去关那个黑窗口。 反过来做最容易丢存档。

备份（每天或每次大规模战斗前）

  1. 进「存档备份」；
  2. 备注写清楚，例如 Day12 破城前；
  3. 点立即备份，等进度结束；
  4. 确认列表里多了一条、大小和存档量级相符。

恢复

  1. 先停止服务器（运行中恢复会被拒绝）；
  2. 找到目标备份，点恢复；
  3. 重新点启动服务器，等 serving。

改配置的顺序（别搞反）

  1. 控制台里停止服务器；
  2. 「配置」页改好 → 校验并保存；
  3. 关闭黑窗口，重新双击 start-console.bat；
  4. 再点启动服务器。

长期挂机

控制台跑在伪终端里，窗口关掉服务器就停。要长期开：把黑窗口最小化别关， 并在 Windows 电源设置里关掉"睡眠"，或者用计划任务在开机时拉起 start-console.bat。注意本工具不负责崩溃自动重启。

排障三板斧

现象先看这里
页面打不开黑窗口还在吗？窗口里「监听」那行是哪个地址？防火墙放行了吗？
一直卡在 loading「TUI 镜像」看服务端在干什么；「实时日志」筛"错误"。
数据是空的「配置」页的路径对不对；node lib\config.js 看哪项 ✗。

09安全须知

这是个没有任何登录界面的管理后台：谁打开这个地址，谁就能启停服务器、恢复存档、踢人、发全服公告。 默认监听 0.0.0.0 是为了"解压就能用"，代价是它能被同一网络里的任何人打开。

按你的场景选一种

场景建议
只在自己电脑上用 host 改成 127.0.0.1。最简单也最安全。
自己和朋友在 ZeroTier / 家里局域网 host 改成 auto。只放私有网段，公网网卡不监听。
机器有公网 IP 用 auto，并且一定加访问口令（见下），或者干脆别开这个端口。

加访问口令

启动前设置环境变量 COOP_CONSOLE_TOKEN，之后所有请求都要带口令：

set COOP_CONSOLE_TOKEN=换成你的一串随机字符
start-console.bat

带口令有三种方式，任选其一：

  • 网址后缀：http://127.0.0.1:7788/?token=你的口令（之后会写进 Cookie）
  • 请求头：X-Console-Token
  • Cookie：coop_console_token
另外两件事：
1. 控制台会执行你输入的任何服务端命令，包括作弊命令。别把地址给不熟的人。
2. 备份目录里是完整存档，等于所有人的游戏进度。分享截图时注意别把路径和 SteamID 一起发出去。

10常见问题 FAQ

Q1　双击 bat 窗口一闪就没了

先看是不是没装 Node.js：窗口里会打印 Node.js not found。 装 Node 18 以上（推荐 22 LTS），重开即可。若装过还是闪退， 在本目录打开 PowerShell 执行 node server.js，报错会停在屏幕上。

Q2　页面能开，但一直显示"未运行"

点右上角启动服务器。控制台自己不会去拉服务端，需要你点一下。

Q3　点启动后很快变成"已停止"

服务端起来就崩了。切到「TUI 镜像」看最后几行，通常是：
· 游戏版本不对（需要 Native v1.4.8.118999）
· Coop 模组版本不对（需要 v0.1.6）
· 端口被占用（换个 gamePort，或先关掉占用的进程）
· 存档损坏（用「存档备份」恢复一个）

Q4　玩家档案是空的

两段数据各有条件：存档配对文件要服务端存过盘、且跑过一次；玩家详情要游戏内 CoopPlayerCard 模块部署过，并且服务端跑到读档完成之后才会有。 页面底部那行小字会告诉你当前读的是哪个文件、什么时候更新的。

Q5　地图一片空白 / 只有海

地图由底图 + 120 个聚落坐标组成，坐标来自服务端的 settlements.xml。 若只有底色，说明客户端没加载到 public/img/calradia.jpg—— 检查压缩包是否解压完整（该文件约 2.5 MB）。

Q6　日志里全是红字堆栈

遥测上传失败，每 60 秒一次，不影响任何功能。勾上「隐藏堆栈噪音」即可。

Q7　中文乱码 / 显示方块

服务端是英文环境，中文来自随包的中文语言文件。若聚落名显示英文， 说明没找到 engine\Modules\*\ModuleData\Languages\CNs， 检查 serverDir 是否指对。界面本身的中文不受影响。

Q8　端口 7788 被占用

换一个：start-console.bat 7790，或在「配置」页把端口改成 7790 再重启。 想找出谁占了：netstat -ano | findstr :7788。

Q9　关掉黑窗口后玩家掉了

正常。服务端跑在那个窗口的伪终端里。要长期开就别关它（最小化可以）。

Q10　改了配置怎么没生效

因为配置在控制台启动时读进内存。改完要重启控制台（连带重启服务端）。 「配置」页每栏底部的灰字会显示「当前值来自 …」，能看出是不是被环境变量或命令行压住了。

├─ data\                    命令表、更新日志缓存

├─ tools\                   自检与自测脚本
└─ docs\                    本手册 PDF 与界面截图

拿到包之后建议做的三件事

  1. node lib\config.js —— 确认三个路径都是 ✓；
  2. 双击 start-console.bat —— 确认窗口里打印出了可访问地址；
  3. 浏览器进「配置」页 —— 按自己的网络环境把监听地址改成 auto（只放内网）或 127.0.0.1（只本机）。
包里的 node_modules 是 Windows x64 的预编译产物。 不需要 npm install，也不需要 Visual Studio / Python。 如果你在 ARM 版 Windows 或其它系统上跑，才需要自己重新装依赖。

卸载

直接删掉整个文件夹即可——它不写注册表、不装服务、不改系统。 唯一留在外面的是 Documents 下的 CoopData（那是游戏自己的存档，删之前想清楚）。
